## はじめに

ZEN大学で知能情報を学んでいる2年生の松延です。AIエージェントを個人開発していますが、仕事で機械学習をした経験はありません。

LLMは普段APIやエージェント経由で使っていますが、中で何が起きているかを自分の手で確かめたくなりました。そこで、外部の学習済み重みも高水準ライブラリも使わず、PyTorchの基本演算だけで日本語の小さなGPTを作りました。さらに、モデルが自分の回答を自分で採点して学び直す「RSI（再帰的自己改善）」の真似ごとも、おもちゃ規模で試しました。

先に正直に書いておくと、これは **学習データが数KBしかない教育用の小さなモデル** です。実用性は期待しないでください。RSIの結果も、後半で書くとおり「おもちゃの設定での、自分で書いた採点ルールによる数字」です。AGIのような話ではありません。

## 何を作ったか

約90万パラメータの、文字単位の日本語 Decoder-only Transformer（Mini-GPT）です。3段階で作りました。

1. `mini_gpt.py`：文字単位トークナイザーとTransformer本体。日本文学の冒頭抜粋で事前学習して、続きの文を生成する。
2. `chat_gpt.py`：同じ構造のまま、`ユーザー: ...\nAI: ...◁` 形式の会話データで学習してチャットボットにする。
3. `rsi_gpt.py`：モデルが複数の返答候補を作り、自分で採点して、良いものだけを学習データに足して再学習する。

ほかに、標準ライブラリの `http.server` だけで動くローカルWeb UI（`web_ui.py`）があります。最初の1文字目の予測確率トップ5を見たり、会話データを編集してその場で再学習したりできます。

## 仕組み

### 1. Transformer最小構成（mini_gpt.py）

ハイパーパラメータは小さく、埋め込み128次元・4ヘッド・4層です（`mini_gpt.py`）。

```python
BLOCK_SIZE = 64       # 最大の文脈長
N_EMBD = 128          # 埋め込みベクトルの次元数
N_HEAD = 4            # Attentionヘッドの数
N_LAYER = 4           # Transformerブロックの層数
```

核になるのはCausal Self-Attentionです。未来の文字を見ないように、下三角マスクをかけてからsoftmaxします。

```python
att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(head_dim))
att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
att = F.softmax(att, dim=-1)
```

ブロックはPre-LayerNormで、残差接続を2回挟むだけの構成です。

```python
def forward(self, x):
    x = x + self.attn(self.ln1(x))  # 残差接続 + Attention
    x = x + self.mlp(self.ln2(x))   # 残差接続 + FeedForward
    return x
```

トークナイザーは「学習データに出てきた文字に番号を振るだけ」です。

```python
chars = sorted(list(set(text)))
stoi = {ch: i for i, ch in enumerate(chars)}
```

事前学習版（語彙377文字、文脈長64）のパラメータ数は898,425です。`PAPER.md` の記載値で、層ごとの式から手計算しても一致しました。

### 2. 会話チューニング（chat_gpt.py）

ネットワーク構造は変えていません。変えたのは2点だけです。

- 入力を `"ユーザー: {質問}\nAI: "` という形に整える。
- 学習データのAI返答の末尾に終了記号 `◁` を付け、生成中に `◁` が出たらそこで止める。

```python
if token_id == stop_token_id:
    break  # 終了記号(◁)が出たら発言を終了！
```

終了記号がないと、モデルは返答のあとに「ユーザー: ...」まで勝手に続きを書いてしまいます。これが後で出てくる「役割漏洩」です。

### 3. RSIループ（rsi_gpt.py）

やっていることは、Best-of-N の棄却サンプリング（STaRやReSTに近い考え方）の小規模版です。

1. 7個の質問それぞれに、返答候補を N=6 個生成する。
2. 100点満点のルールで自己採点する。
3. 最高点の候補が75点以上なら、「質問と返答」のペアを合成データとして採用する。
4. 合成データを会話データに足して、350ステップ再学習する。これを3世代繰り返す。

採点ルールは次の4項目の合計です（`evaluate_candidate`）。

| 項目 | 配点 | 内容 |
| --- | --- | --- |
| 完結性 | 25 | `◁` で自然に終わった |
| 形式 | 25 | 「ユーザー」「AI:」の混入・改行・同じ文字4連続以上がなく、12文字以上 |
| 質問への適合 | 最大30 | 質問ごとに私が決めたキーワードが含まれる（1語15点） |
| 自己確信度 | 最大20 | 生成時にモデル自身が選んだ文字の平均確率 × 20 |

```python
matched_kw = [kw for kw in prompt_info["keywords"] if kw in reply]
kw_score = min(30.0, len(matched_kw) * 15.0)
...
conf_score = round(candidate["avg_confidence"] * 20.0, 1)
```

探索温度は世代ごとに下げています（`max(0.45, 0.85 - (gen - 1) * 0.12)`）。つまり0.85、0.73、0.61です。

## 結果

出典は `PAPER.md` と `rsi_history.json` です。`rsi_history.json` の値は私も集計し直して確認しました。

**事前学習**（日本文学の冒頭抜粋 1,678文字、語彙377文字、800ステップ）：損失は Step 1 の 6.1098 から Step 800 の 0.0683 まで下がりました。「吾輩は」に続けて「猫である。名前はまだ無い。…」と出力します。

**会話チューニング**（27組の問答、1,575文字、1,000ステップ）：損失は Step 1 の 5.5833 から Step 1000 の 0.0387 まで下がりました。

**RSI（7個の質問、N=6、閾値75点、各世代350ステップ）**：

| 世代 | 探索温度 | 最良候補の平均点 | 最悪候補の平均点 | 最悪が75点未満の質問 | 再学習後の損失 |
| --- | --- | --- | --- | --- | --- |
| Gen 1 | 0.85 | 97.56 | 80.77 | 4/7 | 0.0635 |
| Gen 2 | 0.73 | 97.84 | 97.80 | 0/7 | 0.0490 |
| Gen 3 | 0.61 | 97.84 | 97.80 | 0/7 | 0.0639 |

Gen 1 の失敗例は次のようなものです。

- 「こんにちは！元気？」に「こんばんは！今日もお疲れさまでした。…」（69.8点）
- 「LLMとAttentionについて教えて」に、返答の中へ「Attentionって何？\nAI: …」と書いてしまう役割漏洩（74.9点）

最悪候補の平均点は 80.77 から 97.80 へ上がり、75点未満の質問は4/7から0/7になりました。ただし、この数字を「モデルが賢くなった」証拠として読まないでください。理由は次の章に書きます。

## 限界と注意点

- **データが極端に少ない。** 事前学習データは1,678文字（約5KB）、会話データは27組です。損失が0.04〜0.07まで下がるのは、汎化しているというより、ほぼ暗記しているからだと考えています。検証用データを分けて測っていないので、汎化性能の数字は一つもありません。
- **RSIの評価質問と学習データが同じ。** 採用された7組の合成データは、評価に使った7個の質問そのものに対する返答です（`chat_data.txt` の末尾に入っています）。Gen 2・Gen 3 は、答えを学習データで見た質問をもう一度解いているだけです。点数が上がるのは当然で、未知の質問への改善を示してはいません。
- **採点者は自分自身（と私のルール）。** 点数を付けているのは、私が書いたルール、私が選んだキーワード、そしてモデル自身の確信度です。自己採点には「ルールに合うものが高得点になる」というバイアスがあります。確信度の項は、暗記した答えほど高くなりやすいです。
- **別の要因が混ざっている。** 世代ごとに探索温度も下げています。温度を下げるだけでも、でたらめな出力は減るはずです。RSIの効果と温度の効果は分けて測っていません。
- **記録があるのは1回分の実行だけ。** 乱数シードを変えた繰り返しや、RSIなしの場合との比較は、記録に残していません。
- **実用性はない。** 学習データにない話題を聞くと的外れな返答になります。README にも同じ注意書きがあります。

RSIという名前は付けていますが、実際にやったのは「小さなモデルが自分の出力から良いものを選び、同じ質問の答えを覚え直した」ことです。

## 動かし方

```bash
pip install -r requirements.txt   # torch>=2.0.0

python mini_gpt.py                # 事前学習と文章生成
python chat_gpt.py                # 会話データで学習（chat_model.pt を保存）
python chat_gpt.py --chat         # 保存済みモデルと対話
python web_ui.py                  # ローカルWeb UI（http://localhost:8765）
python rsi_gpt.py                 # RSIを3世代回す
```

注意として、`rsi_gpt.py` は実行すると `chat_data.txt` を書き換えます。試すときはバックアップを取ってください。ブラウザで試すだけなら、下のデモSpaceが手軽です。

## まとめ

- PyTorchの基本演算だけで、約90万パラメータの日本語GPTを作りました。`mini_gpt.py` は全体で175行（コメント込み）で、一通り読めます。
- 構造を変えずに、プロンプトの形と終了記号だけで「続きを書くモデル」を「会話するモデル」にできました。
- RSIの数字は、おもちゃの設定での自己採点の結果です。評価質問が学習に混ざっているので、一般的な自己改善の証拠にはなりません。次にやるなら、評価用の質問を学習から分けること、採点を自分のルール以外にすること、温度を固定することだと考えています。
